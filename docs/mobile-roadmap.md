# スマートフォンアプリ化の方針

現在は依存ライブラリなしの HTML / CSS / JavaScript。GitHub Pages の同じURL・同じ保存キーを維持しています。今回はネイティブへの全面移行や Capacitor の導入はしていません。

## 自然な次の一歩：Capacitor

現在のオフィス、受注票、ハンコ、紙の演出、Web Audioを保持したい段階では Capacitor で包む方法が自然です。将来の webDir は `dist`。iOS用プロジェクト・署名・App Store審査・実機での音声やキーボードの検証は、その段階で追加します。Web版も同時に維持できます。

## 現在の責務分離

- `dist/js/domain.js`：データ移行、日付、成長計算、受注・完遂のデータ更新。DOMと保存に依存しません。
- `dist/js/storage.js`：保存キーと読込・書込・バックアップ形式を一元管理。現在は localStorage。
- `dist/js/screens.js`：本社、案件の分類、設備、表彰、総務の表示用処理。設備・表彰は定義を追加できる構造。
- `dist/js/events.js`：既存の3種類のお祝いと音声、手動で閉じる進行。
- `dist/js/platform.js`：端末機能の境界。現在は対応ブラウザでの振動。
- `dist/app.js`：画面ルーティング、フォーム、各層の接続。`bootstrap.js` が初期化。
- `dist/js/icons.js`：絵文字に依存しないSVGアイコン。

スクリプトはビルド不要の小さなモジュールに分割し、読み込み順はHTMLで明示しています。将来のES Modules化も可能です。保存処理は画面の描画には直接書きません。Capacitor Preferences等の非同期保存へ移る際は、起動時の読み込みと書き込み完了待ちをストレージ境界・コントローラで追加します。

## ネイティブへ移行する判断

複雑なネイティブ操作や長い一覧の性能、iOS標準の操作感が重要になった段階でReact Native等を検討。JavaScriptの成長計算・日付・データ形式は再利用でき、画面・音声・保存・端末機能は置き換えます。Swiftの場合はルールを移植し、同じ境界テストで確認できます。現時点では演出を再実装する費用に対しCapacitorの利点が大きいと判断しています。

## 保存・通知の注意点

GitHub Pagesとネイティブアプリの保存領域は別です。自動共有されないため総務部のJSON書き出し・読み込みを移行経路とします。旧版の集計EXPは保持しますが、保存されていなかった完遂案件名や過去の成長日時は復元・捏造しません。

今回の「期限のお知らせ」は本社を開いたときのアプリ内案内です。バックグラウンド通知は未実装。アプリ化の際に権限とローカル通知の登録・変更・取消を端末層に追加します。iPhoneでの振動はWeb版では非対応の場合があり、ネイティブHapticsへの交換を想定しています。
